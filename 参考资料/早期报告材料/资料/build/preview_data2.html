第0章 数据是什么：四种角色与五段流向

在智能制造里，“数据”不是 Excel 里的一堆数字，而是能驱动动作的事实记录。同一个瓶盖被检测一次，会同时产生四类性质完全不同的数据；分不清它们，后面的指标、阈值、日志都会算错。

0.1 课堂上说的“数据”，其实是四种东西

第 1–4 讲里出现的每一个量，都可以归到下面四类角色里。判断一个量属于哪一类，只要问一句：它会不会随时间、随产线状态变化？

最常见的混淆

把“规则参数”当成“计算结果”：阈值 0.9 不是模型算出来的，是人按风险偏好设定的。

第1章 系统、流程与处置数据

第 1 讲回答“系统由什么组成、怎样运转”。把它翻译成数据语言，就是：六类要素各自产生什么数据、缺陷用什么标签表示、一件产品的处置结果如何编码。

为什么“信息”要素单独列

人员、设备、物料、工艺、环境是“产生数据的对象”，信息是“被这些对象产生和交换的结果”。

所以信息类字段最多：信号、图像、分数、处置、时间戳都在这一栏。

一句话区分信息流与控制流

“疑似缺口 0.91”是信息流：它描述状态。

“进入复检通道”是控制流：它要求设备做动作。

控制流不是电流，而是“要求设备做什么”。

 

1.6 闭环的关键：结果必须回写

没有回写就没有闭环。系统必须把“做了什么、成没成功”记下来并送回数据层，否则下一次感知和决策用的还是旧假设。

• 执行结果回写：动作是否真的发生、作用在哪个瓶盖上（确认传感器）。

• 判断结果回写：这一件的类别、分数、处置，与图像 ID 绑定。

• 异常回写：没拍到、模型不确定、执行失败，各自形成报警事件。

• 统计回写：按班次、批次、型号汇总，形成趋势与阈值调整依据。

3.3 confidence 是什么、不是什么

confidence（置信度）= 模型对这一次预测的把握程度，是一个 0–1 的分数。它不是“模型正确率”，更不是“这只瓶盖真有缺陷的概率”。

要评估准确率，只能在有标签的测试集上统计——那是第 3.7 节混淆矩阵的事。

4.9 数据要能“回放”

出质量事故时，最重要的是能复现：哪一张图、哪一版模型、哪个阈值、哪个时刻、哪个动作。所以下面五项必须能关联起来，缺一项就无法回放。

• 图像（或图像 ID + 保留路径）

• 模型版本与阈值参数版本

• 完整时间戳链（t0…t4）

• 处置与执行确认结果

• 设备状态与异常事件（当时的气压、光照、带速）

本章小结

质量规则是可执行的数值参数；阈值 0.5／0.9 是系统参数，不是模型属性。

每个事件都要有时刻：节拍 500 ms/件 与推理 800 ms/次 的差距就是落地难点。

图像坐标 ≠ 物理位置；延时 Δ = 距离 ÷ 带速，带速变了要重算。

五类运行记录缺一不可，否则无法追溯与回放。

5.2 字段命名规范（☆ 建议直接采用）

• 小写下划线：`cap_id`、`ts_capture`、`model_ver`，不要用中文或空格。

• 单位进名字：`delay_ms`、`belt_speed_mm_s`、`area_mm2`，避免“到底是秒还是毫秒”。

• 时间统一 ISO 8601 带时区：`2026-11-04T21:52:33.412+08:00`，不要存“11/4 21:52”。

• 枚举用大写常量：`PASS`／`RECHECK`／`REJECT`，不要存 0/1/2 却不写字典。

• 版本必带：`model_ver`、`rule_ver`、`calib_ver`，换版后数据才可比较。

• ID 唯一且可追溯：瓶盖 ID 与批次号、图像 ID 三者能互相找到。

5.3 初学者最容易踩的 15 个数据陷阱

1. 把 confidence 当准确率。 0.91 只是本次预测分数，准确率要在测试集上算。

2. 把“阈值”混成一个词。 图像二值化阈值（0–255）与决策阈值（0–1）是两回事。

3. 单位不统一。 一处写 800（ms），一处按秒算，节拍结论立刻错。

4. 时间戳不带时区。 跨班次、跨设备对不齐，回放时谁先谁后说不清。

5. 图像坐标当物理位置。 拍完就推，必然推错或推空。

6. 固定延时用在变速产线。 带速一变，Δ 就失效。

7. 只看准确率验收。 98% 可能一只缺陷都没抓到（见 3.9 节）。

8. 把 RECHECK 算作不良。 复检通道不是废品通道，混算会虚高不良率。

9. 类别不均衡没处理。 正常品远多于缺陷，模型“全判正常”也能拿高分。

10. 训练/测试数据泄漏。 同一只瓶盖的图像同时进了训练和测试，指标虚高。

11. 标注口径不一致。 两个人对“划痕”的判定不同，标签本身就带噪声。

12. 采样率不足。 拍照帧率低于产线节拍，漏拍发生在数据层，算法再好也没用。

13. 只存结果不存图像。 判了 REJECT 却无法复核，客户投诉时无从解释。

14. 阈值写死在代码里。 换产品、换标准就要改代码，无法按批次调整。

15. 忘了记模型版本。 换了模型后指标变化，却分不清是模型还是数据的功劳。
