# 瓶盖智能质检 · 串联判断演示（特征识别）

一句话：**把“异常分 + 轻量分类器”这套串联判断，做成能点、能看、能验证的程序。**

- 判断逻辑：`特征测量 → 异常分（门卫）→ 分类器（分诊台）→ 处置（PASS / RECHECK / REJECT）→ 执行 → 记录`
- 阈值只用 **train（160 张）** 定，**val（40 张）** 只用来评一次，不参与调参
- 不依赖深度学习框架：只用 `numpy + Pillow + tkinter`，装上 Python 就能跑
- 所有接口都留了扩展位：接相机、接红外、接电机、换界面都不用改判断逻辑

## 2. 界面怎么看（从上到下四块）

| 区域 | 看什么 | 想说明什么 |
|---|---|---|
| 左上：原图 + 叠加层 | 深蓝圈 = 拟合出的外圆，橙色十字 = 圆心，青色小点 = 被判为“偏亮”的像素 | 程序不是“看整体”，而是先找到圆心和半径，再在规则坐标里量 |
| 左下：摊平偏差图 | 横轴是绕一圈的角度，纵轴是半径；红色偏亮、蓝色偏暗、灰色正常 | 环纹被减掉后，缺陷会单独显形 |
| 右上 ①：四个特征 | 每行是“数值 / 阈值 / 超标多少倍”，超过 1.0 倍标红 | 判断依据是四个可解释的数，不是一个黑盒分数 |
| 右上 ②：异常分 | 绿 / 橙 / 红 三段色条 + 指针；标注 low、high 两个阈值 | 异常分只回答“离正常多远”，能抓住没见过的缺陷 |
| 右上 ③：四类概率 | 四条横条，最高的一项是预测类别 | 分类器只回答“像哪一类”，并给出置信度 |
| 右上 ④：结论 | `PASS` / `RECHECK` / `REJECT` + 一句理由 + 各段耗时 | 处置才是系统要输出的东西；类别只是附带的统计信息 |
| 底部：表格 + 统计 | 每张图一行；右侧汇总准确率、处置率、漏检、误剔、复检率、平均耗时 | 一眼看出这套判断在 40 张 val 上的真实表现 |

底部还有两个滑块（**临时试算**）：拖动 `low` / `high` 可以立刻看到结论怎么变，**不会写回配置文件**——用来在答辩时演示“阈值是风险偏好”。

### 4.1 阈值是怎么调到“最优”的

| 步骤 | 命令 | 做什么 |
|---|---|---|
| 1 | `python tune.py` | 只用 **train** 定特征阈值、异常分基线，并用 5 折交叉验证挑分类器 |
| 2 | `python optimize.py` | 只用 **train** 把 `low / high / conf_min` 放进“正常品最高分 ~ 缺陷最低分”的空档带，并打印新旧阈值对比 |
| 3 | `python evaluate.py --split val` | 在 **val** 上只评一次（val 不参与任何调参） |

产出的关键结论：

- **四类准确率与阈值无关**——准确率只取决于分类器给的概率，阈值只决定“处置”。
- train 上正常品最高 0.1879、缺陷最低 0.8647，中间 0.68 宽是空档带；把复检带放进空档带，就能同时做到零漏检、零误剔、零复检。
- 旧阈值（0.8214 / 0.9868）的 `high` 落在缺陷分布内部，所以 30 张缺陷里有 5 张只能进复检；新阈值把它们直接判成 REJECT。

### 4.2 “零复检”是什么意思？——风险偏好与漂移压力测试

**先把话说清楚：零复检 ≠ 没有缓冲带。** 缓冲带一直都在，只是这批（合成）数据的正常品分数（0.015~0.116）和缺陷分数（0.947~1.000）隔得很远，没有任何样本落进带子里。如果分数一漂移、有样本落进 `[low, high)`，它们就会自动走复检。

**但“阈值放在空档带哪里”确实是一个风险偏好问题，这里可被批评。** 两种放法：

| 策略 | low / high | 复检带宽度 | 特点 |
|---|---|---|---|
| 均衡（最大裕度） | 0.39 / 0.66 | 0.27 | 两侧各留 0.20 裕度，机器自己拍板的比例最高 |
| **保守（风险厌恶，当前默认）** | **0.22 / 0.83** | **0.61** | low 贴着正常包络、high 贴着缺陷包络，“拿不准就交人工” |

`python stress.py` 用同一份分数做压力测试（`python stress.py --fig` 另出 `out/fig_drift_stress.png`）：

| 情形 | 均衡 0.39/0.66 | 保守 0.22/0.83 | 旧 0.82/0.99 |
|---|---|---|---|
| 缺陷分数整体下降 0.20，漏检率 | 0% | 0% | **100%** |
| 缺陷分数整体下降 0.10，漏检率 | 0% | 0% | 2% |
| 新缺陷分数均匀铺在 0~1 时被拦下的比例 | 61% | **78%** | 18% |
| 轻度新缺陷（≈0.5 附近）被拦下的比例 | 77% | **97%** | 2% |

读法（也是答辩时的标准回答）：

1. **漏检比复检贵两个数量级**（漏检 = 缺陷流到客户手里；复检 = 多花一次人工）。所以 `low` 该压低到正常包络附近，而不是放在空档正中。
2. 当前默认取**保守**：把 `low` 压到 0.22、`high` 抬到 0.83，用“多一点复检”换“少一点漏检”。在这 40 张 val 上指标一模一样（97.50% / 100% / 漏检 0 / 误剔 0 / 复检 0），**代价在真实产线上才显现**：会更频繁地触发复检。
3. 想复现“零复检是阈值位置造成的”这句话：把预设切到「演示·会触发复检」（0.82/0.99），复检立刻变成 5 张（12.5%）。

## 5. 目录结构

```
特征识别/
├─ config.json          ← 所有参数（阈值、路径、特征参数）都在这一个文件里
├─ gui.py               ← 可视化界面（只负责显示，不参与判断）
├─ pipeline.py          ← 主流程：一张图 → 一条记录
├─ features.py          ← 特征测量（圆心、半径、摊平、残差、四个特征）
├─ anomaly.py           ← 异常分（正常品基线 + z 分数）
├─ classifier.py        ← 四类分类器（规则/最近质心/逻辑回归/决策树）
├─ tune.py              ← 只用 train 定阈值（特征阈值/异常分基线）+ 交叉验证选分类器
├─ optimize.py          ← 只在 train 上把 low/high/conf_min 放进空档带（--policy 选风险偏好）
├─ stress.py            ← 漂移压力测试：不同阈值在“分数漂移 / 未知缺陷”下的表现
├─ decision.py          ← 串联决策（两条阈值链 → PASS/RECHECK/REJECT）
├─ devices.py           ← 检测输入 / 执行输出 / 记录（接口 + 仿真实现）
├─ evaluate.py          ← 评估：混淆矩阵、处置率、漏检、误剔、按 severity
├─ make_figs.py         ← 生成 decision flow 与阈值敏感性两张图
├─ model/               ← 训练产物（baseline.json / classifier.json / thresholds.json）
└─ out/                 ← 输出（records.csv、评估报告、图片、阈值扫描）
```

## 6. 三个常用命令

```bat
:: 1) 只用 train 重新定特征阈值 / 异常分基线、重新选分类器（会覆盖 model/*）
python tune.py

:: 2) 只用 train 把决策阈值（low / high / conf_min）调到最优位置（必须在 tune.py 之后跑）
python optimize.py

:: 3) 在 val 上评估一次，生成 out/eval_report_val.md
python evaluate.py --split val

:: 4) 重新生成两张图（图里的阈值自动读 config.json）
python make_figs.py
```

## 7. 常见问题

**Q：为什么不用深度学习？**
A：这套数据只有 160 张训练图，而缺陷是“几何可量”的（缺口=轮廓凹陷、污渍=暗斑面积、划痕=直线）。用四个可解释特征 + 轻量分类器，train 上 5 折 CV 已达 97.5%，同时每个数字都能指着图解释——答辩时这一点比多 1% 准确率更值钱。深度模型我们放在“方案比较”里，作为另一条路线。

**Q：为什么有两个阈值？**
A：它们管的是两件事。异常分阈值管“放行/复检/剔除”，分类置信度阈值管“敢不敢把类别写进记录”。只看其中一个都会漏掉一类错误（详见 `TECHNICAL.md` 第 3 节）。

**Q：异常分和分类器会不会打架？**
A：会，所以我们规定了顺序和优先级：**分数 ≥ high 一定不放行**（哪怕分类器说 normal）；**分数 < low 但分类器说缺陷**，也进复检而不是放行。规则写在 `decision.py`，是一个纯函数，可以用单元测试固定住。

**Q：能接真实相机 / 电机吗？**
A：接口已经留好：`devices.py` 里 `FrameSource` 有三个实现（文件 / 相机 / 传感器触发），`Dispatcher` 有日志版与仿真执行版。接真实设备只需要实现这两个类，`pipeline.py`、`decision.py` 一行都不用改。

**Q：界面能换吗？**
A：能。判断部分全部在 `pipeline.Inspector.inspect()` 里，返回一个 `InspectionResult` 对象；界面只是把这个对象画出来。换网页版、换 Qt，都不需要动判断逻辑。
