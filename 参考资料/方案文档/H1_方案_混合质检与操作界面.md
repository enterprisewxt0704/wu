# H1 瓶盖智能质检与自动处置原型 · 方案（待确认）

> 结论先行：**主判决采用「混合串联」——无监督异常分做门卫，有监督分类器做分诊，规则层出 PASS / RECHECK / REJECT；MobileNetV3 不进入主判决，只保留为可选第二意见与对照实验。**
> 界面从现在的“演示面板”升级为「操作台（简洁）+ 诊断页（答辩）」；设备层统一抽象为接口，现在用仿真闭环，真实相机 / 对射光电 / RoboMaster / PTK / 达妙按同一接口接入。

---

## 0. 一句话方案

```
对射光电到位 → 工业相机抓图 → 质量门 → 特征测量（4 个可解释特征 + 缺陷位置）
→ 异常分（只学正常品，抓未知缺陷） → 分类器（4 类 + 置信度）
→ 三分支决策（low / high / conf_min） → 执行机构（三通道）
→ 执行确认 + 逐只记录 + 界面统计
```

- **主判决不依赖 GPU / torch**：numpy + Pillow + tkinter，答辩机装了 Python 就能跑。
- **MobileNetV3 作为可选后端**：接口留好，装了 torch 就能在同一批 val 上做“纯深度 vs 混合”对照，不装也不影响原型。
- **仿真与真实共用一条流水线**：`LineController` 只依赖 `FrameSource / Dispatcher / Recorder` 三个接口，换设备不改判断逻辑。

## 2. 方案比较与选型

### 2.1 三条候选路线

| | A. 纯深度学习（基础版） | B. 纯手工特征 / 异常分 | **C. 混合串联（选中）** |
|---|---|---|---|
| 判决依据 | MobileNetV3 四类概率；缺陷分 = 3 个缺陷概率之和 | 4 个可解释特征 + 正常品基线异常分；规则分类 | 异常分（门卫）+ 分类器（分诊）+ 规则三分支 |
| 类别输出 | 有，且是主输出 | 规则分类可给，但弱 | 有，logreg 概率 |
| 未知缺陷 | 会硬塞进 4 类，可能塞成 normal | 能报警，但说不出类别 | 能报警 + 能标“未知缺陷” |
| 可解释性 | 弱（黑盒概率） | 强（每个数能指图） | 强（分数 + 特征 + 类别三份证据） |
| 数据要求 | 需要较多标注；本数据仅 160 张 train | 只需正常品定基线 | 同 B + 标注训练分类器 |
| 运行依赖 | torch + torchvision（约 2 GB），有 GPU 更好 | numpy + Pillow | numpy + Pillow（可选 torch） |
| 本机实测 | 课程 README：val 39/40（97.5%），但 `img_2_045` 划痕被判 normal，靠阈值进复检 | val 97.50%，缺陷处置率 100% | 同 B（当前实现即 C 的轻量版） |
| 主要风险 | 单模型错误直接变成处置错误；换光源/新缺陷时无兜底 | 类别统计弱；阈值依赖正常品分布 | 两个模型都要维护；但接口隔离后成本低 |

### 2.2 为什么选 C，不选 A 或 B

1. **H1 要的是“处置正确”，不是“分类准确”**。漏检（缺陷流到客户）比复检贵两个数量级。纯分类器把“没见过的缺陷”硬塞成 normal 时，系统会直接放行；异常分只回答“离正常多远”，正好补这个洞。
2. **课程数据只有 160 张 train、且是合成图**，深度网络相对手工特征的增益有限；H1 又明确“不要求自行训练复杂深度学习网络”。把 MobileNetV3 放在“方案比较”里当对照，比把它当主判决更稳。
3. **基础版自己就暴露了单模型风险**：`img_2_045` 划痕被判 normal，只是因为缺陷分过阈值才进复检——这正好是“两条链串联”的论据。
4. **可解释性直接换分**：答辩被问“为什么判缺陷”时，能指出 `purity=8.0`（阈值 2.7）、摊平图上的斜线、异常分 0.984，比“模型输出 0.98”更有说服力。
5. **工程可复现**：numpy-only，答辩机零依赖；9 ms/件，节拍余量 50 倍以上。

### 2.3 MobileNetV3 怎么处理（不浪费这份资产）

- 新增 `CategoryModel` 抽象，现有 `logreg` 是默认实现；
- 预留 `DeepCategoryModel`（torch）：加载 `model.pth`，输出四类概率；
- 配置开关 `model.backend = "logreg" | "mobilenetv3"`；
- 若答辩机可装 torch：在 val 40 张上跑「纯 MobileNetV3」「纯特征」「混合」三行对照表，放进报告“方案比较”；
- 若装不了：引用基础版 README 的 39/40 结果做定性比较，不伪造运行数据。

## 3. 判断链路（核心）

### 3.1 五阶段与证据

```
① 质量门      尺寸/曝光/清晰度/瓶盖是否居中  → 不合格直接 RECHECK（不进模型）
② 特征测量    圆心、半径、极坐标摊平、减环纹 → notch / dark / purity / peak + 缺陷掩码/位置
③ 异常分      正常品 median/MAD → 每特征稳健 z → score = 1 - exp(-max_z/2) ∈ [0,1)
④ 分类器      4 类概率（logreg；可选 MobileNetV3 第二意见）
⑤ 决策        纯函数 decide(score, pred, proba, cfg) → PASS / RECHECK / REJECT + reason + is_unknown
```

### 3.2 三分支规则（与现有 `decision.py` 一致）

| 条件 | 处置 | 物理含义 | 记录里必须有的字段 |
|---|---|---|---|
| `score < low` 且 `pred == normal` 且 `p_normal ≥ pass_normal_prob` | **PASS** | 两份证据都指向正常，才放行 | score、pred、conf、reason |
| `low ≤ score < high`，或 `score < low` 但分类器说缺陷 | **RECHECK** | 系统承认不确定，交人工/复检通道 | score、band、worst_feature |
| `score ≥ high` | **REJECT** | 异常分很高，绝不放行；分类器说不清时标「未知缺陷」 | score、is_unknown、act_ok |

- **顺序不能反**：先异常分后分类器；否则“分类器说 normal 就放行”会漏掉新缺陷。
- **阈值只准用 train 定**，val 只评一次；默认 `risk_averse`，界面可切 `balanced` / 演示预设，但“临时试算”不写回配置。
- **输出**：类别、异常分、四类概率、最异常特征、缺陷位置（掩码/外接框）、五个阶段时间戳、处置理由。

### 3.3 质量门（H1 的“输入异常”要求）

在特征测量前加一道轻量检查，全部可配置：

| 检查 | 判据（初值） | 不通过时 |
|---|---|---|
| 图像可读/尺寸 | 512×512，RGB | RECHECK + 报警“无有效图像” |
| 曝光 | 灰度均值在 [40, 220] | RECHECK + 提示补光/曝光 |
| 清晰度 | 拉普拉斯方差 ≥ 阈值 | RECHECK + 提示重新对焦 |
| 瓶盖在视野 | 前景色度像素占比 & 质心偏差 | RECHECK + 提示“未到位/偏出视野” |
| 重复触发 | 同一 `trigger_id` 在最小间隔内重复 | 丢弃并记一条 `duplicate` |

> 这些阈值同样只用 train 统计定，不碰 val；界面里以“设备健康”灯显示。

## 4. 硬件接入设计

### 4.1 总体连接

```
                    ┌────────────── 工业相机（顶拍/斜拍 + 光源）
                    │  GigE / USB3 / 硬触发
对射式红外光电开关 ──┤
（到位信号，~1 ms）  │
                    ▼
            工控机 / PC（Python 原型）
              │        │            │
      USB-CAN │        │ USB/串口    │ 串口/PWM
              ▼        ▼            ▼
        RoboMaster   达妙电机      PTK 舵机
        （传送带/转盘）（剔除推杆） （三通道分流挡板）
              │
              └── 编码器 / 二次光电 / 限位 → 执行确认
```

### 4.2 设备分工（建议，待你确认）

| 设备 | 建议职责 | 接入方式 | 控制量 | 确认方式 |
|---|---|---|---|---|
| 对射式红外光电开关 | 瓶盖到位触发；可再加一只在剔除口做通过确认 | NPN/PNP → PLC / 串口 / GPIO | 上升沿 + 去抖 | 边沿时间戳、触发计数 |
| 工业相机 | 触发抓图；固定曝光/增益；ROI 512×512 | 海康 MVS / 大恒 / UVC（cv2） | 软触发或硬触发 | 帧号、相机时间戳、丢帧计数 |
| RoboMaster 电机（M3508/C620 等） | 传送带调速 / 转盘分度 | CAN（DJI 协议，python-can） | 转速或位置 | 编码器反馈、到位稳定 |
| 达妙电机（DM 系列） | 剔除推杆 / 顶升 / 转盘 | CAN（MIT / 位置模式） | 位置 + 速度 | 位置到达、限位/二次光电 |
| PTK 舵机 | 三通道分流挡板（PASS 直行 / RECHECK 侧道 / REJECT 剔除道） | PWM 或串口总线（按实物） | 目标角度 | 角度回读或限位 |

> 三个执行器不一定都要用上：如果机构只用“一个挡板 + 一条复检通道”，PTK 就够；RoboMaster 负责输送；达妙负责剔除。**具体以你们实际机构为准，我按你确认的拓扑写驱动。**

### 4.3 时序与延时补偿（M1 同款问题，H1 也要讲清）

设光电在 S 点，相机在 C 点（S→C 距离 `d_sc`），执行点在 A 点（C→A 距离 `d_ca`），线速度 `v`：

```
t_trigger = 光电上升沿
t_capture = t_trigger + d_sc / v          # 瓶盖走到相机视野中心
t_decide  = t_capture + 推理耗时
t_act_due = t_trigger + (d_sc + d_ca) / v # 瓶盖走到执行点
补偿量     = t_act_due - t_decide
```

- `LineController` 维护一个“在途队列”（`cap_id, t_trigger, t_act_due, decision`），到点再发执行命令；
- 队列长度 = 在途瓶盖数；界面显示队列深度与最大延时；
- 若 `t_decide > t_act_due`（算不过来/堵料）：报警 + 该只标 `late`，按安全策略处理（默认转 RECHECK，不直接放行）；
- 时间用 `time.monotonic()` 算间隔，记录里另存墙钟时间，便于和视频对齐。

### 4.4 异常与安全（H1“至少两种异常”的落地）

| 异常 | 检测方式 | 处理 |
|---|---|---|
| 相机无图/掉线 | 读帧超时、帧号不连续 | RECHECK + 报警；连续 N 次失败可选停线 |
| 图像过暗/模糊/瓶盖偏出 | 质量门 | RECHECK + 界面提示 |
| 模型不确定 | `low ≤ score < high` 或 `conf < conf_min` | RECHECK / 标未知缺陷 |
| 光电误触发/连触 | 去抖 + 最小间隔 + 重复 trigger_id | 丢弃重复帧并记录 |
| 瓶盖卡住/间距异常 | 光电超时、两次触发间隔过短 | 停线报警 + 人工处理 |
| 执行失败/无确认 | `ActResult.ok=False` 或确认超时 | 重试一次 → 仍失败则报警 + 记 `act_ok=0` |
| CAN/串口断线 | 心跳/异常 | 执行器回安全位、界面红灯、可选停线 |
| 记录写失败 | 写盘异常 | 内存缓冲 + 重试 + 单独报警，不阻塞产线 |
| 断电 | — | CSV 每行 flush；可加 SQLite WAL |

### 4.5 没有实物时怎么演示（H1 视频的兜底）

`SimulatedLine` 用“虚拟传送带时钟”驱动：

- 按 1 件/秒从 val / test_unlabeled 顺序取图，模拟光电触发；
- 执行器按配置延时返回确认，可注入失败率；
- 界面与记录和真实模式完全一致，只是状态栏明确标「仿真执行」；
- 这样 20+ 样本连续运行、≥2 类缺陷、≥2 种处置、结果落盘，全部可录进 5–8 分钟视频。

## 8. 风险与边界（主动说）

1. **数据是教学合成图**：所有指标只证明方法可行，不代表真实产线性能；报告里必须写。
2. **无实物时执行是仿真的**：界面与记录会明确标「仿真执行」，不冒充真实动作；有实物再切换。
3. **MobileNetV3 依赖 torch**：默认不装；只作为可选对照，不影响主原型。
4. **划痕 ↔ 污渍仍会混**：当前 val 唯一错例就是这一类；处置不受影响（都 REJECT/RECHECK），报告里如实写。
5. **阈值不能泄漏 val**：`tune.py` 只读 train，`evaluate.py` 只读 val；界面“保存”才写配置，“临时试算”不落盘。
6. **时序精度**：Python + USB 相机的触发到抓图有抖动；真实联调时要测 `t_capture - t_trigger` 分布，补偿量按实测中位数，不用理论值硬套。
7. **安全**：急停、执行器回安全位、断线检测是原型级，不替代真实产线的安全回路。
