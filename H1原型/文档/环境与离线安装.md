## 2. 为什么是“离线 wheel”

在本机直接 `pip install torch` 会失败：

```text
OSError: [Errno 13] Permission denied: '...\\*.whl.metadata'
```

原因不是网络，而是 pip 下载 metadata 后打开临时文件被系统/沙箱拒绝；`ensurepip` 还会在清理临时目录时报：

```text
PermissionError: [WinError 5] 拒绝访问
```

所以本项目采用：

1. 用标准库 `urllib` 把 wheel 下载到本地；
2. 用 `pip install --no-index --no-deps` 从本地 wheel 安装；
3. 不经过 pip 的在线解析/临时目录。

## 3. 从零重建（可选）

### 3.1 建 venv

```bat
cd /d D:\智造创新实践\H1原型
"C:\Users\wuxuanting\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" -m venv ..\支持文件\Python环境
```

如果 `ensurepip` 报 `WinError 5`，手动把 pip 放进 venv：

```bat
..\支持文件\Python环境\Scripts\python.exe -c "import zipfile; zipfile.ZipFile(r'C:\Users\wuxuanting\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\Lib\ensurepip\_bundled\pip-25.0.1-py3-none-any.whl').extractall(r'..\支持文件\Python环境\Lib\site-packages')"
```

> 这一步只是把 pip 解开，不联网；pip 25.0.1 能用即可。

脚本会下载到 `..\支持文件\离线安装包\wheels\`，带进度和断点大小校验。核心包：

| 文件 | 大小 |
|---|---|
| `torch-2.11.0+cu128-cp312-cp312-win_amd64.whl` | 2,753,189,216 B |
| `torchvision-0.26.0+cu128-cp312-cp312-win_amd64.whl` | 约 9.6 MB |

下载源：

- torch/torchvision：`https://download-r2.pytorch.org/whl/cu128/`
  （`download.pytorch.org` 对脚本可能返回 403，r2 正常）
- 依赖：PyPI（脚本里固定了本机验证过的版本）

### 3.3 离线安装

```bat
..\支持文件\Python环境\Scripts\python.exe -m pip install --no-index --no-deps ..\支持文件\离线安装包\wheels\*.whl
```

注意：

- 必须加 `--no-deps`，否则 pip 会尝试联网解析；
- 顺序不重要，wheel 文件名已带版本；
- `six` 若已存在会跳过，不影响。

### 3.5 完整性检查与自动恢复

`启动.bat` 会先运行 `check_integrity.py --auto`，再打开界面。检查内容：

- 清单共 282 项；其中运行必需文件（`core/ devices/ ui/ 模型/ 数据/`）逐项校验 sha256；
- `config.json`、`README.md`、`启动.bat`、`文档/ 测试/ 工具/` 只查是否存在（这些文件允许手改，不校验哈希）；
- `..\支持文件\Python环境` 的 pyvenv.cfg 与 13 个 Python 包（同时检查 dist-info 和实际包目录）；
- 缺 wheel 时自动调用 `工具\fetch_wheels.py` 下载，再按缺失包名离线安装。

手动命令：

```bat
cd /d D:\智造创新实践\H1原型
..\支持文件\Python环境\Scripts\python.exe check_integrity.py --check
..\支持文件\Python环境\Scripts\python.exe check_integrity.py --auto
..\支持文件\Python环境\Scripts\python.exe check_integrity.py --auto --force
```

恢复来源：

1. 本地缓存 `..\支持文件\安装缓存\H1原型资源.zip`（约 51 MB，含全部项目文件和清单）；
2. 若 `config.json` 的 `integrity.source_base` 配了 HTTP 地址，则下载 `<source_base>/<相对路径>`；
3. 两者都没有时只报告，不静默失败。

> `check_integrity.py --auto` 只补“缺失”的文件；运行必需文件存在但 sha256 不符时默认不覆盖（防止误删手改的源码/模型），确认要恢复时再加 `--force`。

## 4. 没有 GPU / 不想装 CUDA

程序支持**纯特征回退**：

- `config.json` 的 `deep.enabled` 设为 `false`，或
- 直接不装 torch：`DeepModel.load()` 失败不抛异常，`fusion` 自动回退 `M0`。

这样仍可跑完整界面、三通道处置、记录、连续仿真，只是没有 MobileNetV3 的第二票。

如果要在 CPU 上跑深度模型：把 `config.json` 的 `deep.device` 改成 `"cpu"`，并安装 CPU 版 torch（本项目未附带 CPU wheel，需要按 pytorch 官网 CPU 索引自行下载）。CPU 上 MobileNetV3-Small 512×512 单张大约几十到几百毫秒，仍可演示，但节拍会变慢。

## 5. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 状态条“深度模型：不可用（ModuleNotFoundError: No module named 'torch'）” | 没用 `..\支持文件\Python环境` 启动，或 venv 没装 torch | 用 `启动.bat` / `..\支持文件\Python环境\Scripts\python.exe`；按 3.3 安装 |
| `torch.cuda.is_available()` 为 False | 装的是 CPU 版 / 驱动太旧 / 显卡被禁用 | 确认 wheel 是 `+cu128`；更新驱动；`nvidia-smi` 能看见 GPU |
| 首次检测 10–20 s | CUDA/ cuDNN 首次初始化 | 等状态条“就绪”再点；程序内部已 warmup，steady-state 80–100 ms |
| 单张突然 1.6 s | 在**新线程**里首次推理，CUDA 上下文重建 | 已改为单线程推理池；若自己写界面，务必复用同一个常驻线程 |
| `pip` 报 `[Errno 13] Permission denied ...whl.metadata` | pip 在线安装的临时文件权限问题 | 用 3.2/3.3 的离线安装，不要直接 `pip install torch` |
| `ensurepip` 报 `WinError 5` | 临时目录清理被拒 | 按 3.1 手动解压 pip |
| 记录表头错位 | 旧 `records.csv` 是旧 schema | 程序会自动改名 `.old_时间戳`；也可手动删/改名 |
| 界面按钮被截断 | 窗口小于 1280×960 | 已设 `minsize(1120,720)`；建议 1280×960 或更大 |
| 打开图片后没反应 | 深度模型还在加载，任务排队 | 看状态条；等“就绪”后会立刻出结果 |
