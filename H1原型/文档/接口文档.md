# H1 原型接口文档

> 目标：**以后加检测输入、执行输出、反馈记录、换可视化界面时，不需要改判断内核。**
>
> 判断内核 = `core/`（纯 numpy/torch，不 import tkinter）。
> 设备层 = `devices/`（输入、执行、记录、仿真）。
> 界面 = `ui/app.py`（只消费 `InspectionResult`）。
>
> 唯一总装线是 `core/pipeline.py` 的 `Inspector`。界面、批量评估、连续仿真、未来的 Web 服务都调用同一个 `Inspector`，保证“界面看到的结论”和“报告里的数字”同源。

---

## 0. 数据流

```text
┌──────────────┐   Frame(image, ts_sense)   ┌─────────────────────────────┐
│ 检测输入      │ ─────────────────────────► │ Inspector.inspect()          │
│ FrameSource  │                            │  1 质量门                    │
└──────────────┘                            │  2 特征测量 + 异常分         │
                                            │  3 特征分类器 + 深度模型     │
┌──────────────┐   action, ctx              │  4 M0–M3 融合 + 决策         │
│ 执行输出      │ ◄───────────────────────── │  5 记录 + 反馈               │
│ Dispatcher   │   ActResult(ok, ...)       └─────────────────────────────┘
└──────────────┘                                        │
                                                        ▼
                                            InspectionResult（dataclass）
                                                        │
                              ┌─────────────────────────┼─────────────────────┐
                              ▼                         ▼                     ▼
                        tkinter 操作台             CSV/JSONL/SQLite      未来的 Web/大屏
```

`InspectionResult` 是**唯一对外契约**。换界面、加 MES、做离线分析，都只读它，不读内部实现。

## 1. 检测输入：`FrameSource`

### 1.1 契约

文件：`devices/base.py`

```python
@dataclass
class Frame:
    frame_id: str              # 瓶盖 ID / 文件名
    path: Optional[str] = None
    image: Optional[np.ndarray] = None   # H×W×3, RGB, uint8
    ts_sense: float = 0.0                # 光电触发/取图时刻（time.time()）
    meta: Dict[str, str] = field(default_factory=dict)

class FrameSource(abc.ABC):
    @abc.abstractmethod
    def iter_frames(self) -> Iterator[Frame]:
        """持续产出帧；没有新瓶盖时阻塞等待，不要空转。"""
```

### 1.2 已有实现

| 类 | 文件 | 用途 |
|---|---|---|
| `FileImageSource` | `devices/base.py` | 一组图片顺序回放 |
| `FolderSource` | `devices/sources.py` | 文件夹递归找图 |
| `ReplaySource` | `devices/sources.py` | 多轮循环回放 |
| `VideoSource` | `devices/sources.py` | 视频逐帧（需要 `opencv-python`，当前未装） |
| `CameraSource` | `devices/sources.py` | **桩**：工业相机；`open()`/`iter_frames()` 抛 `NotImplementedError` |
| `SensorTriggerSource` | `devices/sources.py` | **桩**：对射光电触发；`iter_frames()` 抛 `NotImplementedError` |
| `ArraySource` | `devices/sources.py` | 内存 ndarray 列表，单元测试用 |

### 1.3 加真实相机（示例骨架）

不要改 `Inspector`；只新增一个 `FrameSource` 子类：

```python
class HikCameraSource(FrameSource):
    def __init__(self, camera_id: str, exposure_us: float = 3000):
        self.camera_id = camera_id
        self.exposure_us = exposure_us

    def open(self):
        # 海康 MVS 示例：
        # self.cam = MvCamera(); MV_CC_CreateHandle(); MV_CC_OpenDevice()
        # MV_CC_SetEnumValue("TriggerMode", MV_TRIGGER_MODE_ON)
        # MV_CC_SetEnumValue("TriggerSource", MV_TRIGGER_SOURCE_LINE0)
        # MV_CC_SetFloatValue("ExposureTime", self.exposure_us)
        ...

    def iter_frames(self):
        while not self.stop:
            # 等光电上升沿（硬触发时相机自己等，主机只取图）
            frame = self._grab_one()          # 返回 H×W×3 RGB uint8
            yield Frame(image=frame, ts_sense=time.time(),
                        frame_id=f"cap_{int(time.time()*1000)}")
```

接好后，只需在构造 `Inspector` 时把 `FrameSource` 传给你的采集循环；`InspectionResult`、界面、记录都不用动。

### 1.4 光电触发要点

- NPN 常开 → PLC 输入 / MCU GPIO / USB 采集卡；串口模块读 `"1"` 上升沿。
- 去抖 10–50 ms；同一只瓶盖挡光期间只算一次，必须“离开→再来”才产生下一事件。
- 触发时刻 `ts_sense` 必须带进 `Frame`，否则无法算在途位置和延时补偿。
- 相机硬触发优先：光电同时触发相机和主机，避免“软件轮询”抖动。
- 输入分辨率不是 512×512 时，在 `FrameSource` 里做居中裁剪/缩放；`DeepModel._prepare()` 也会兜底 bilinear 到 512，但**不要依赖兜底**，否则视野比例会变。

### 1.5 验收

- 连续触发 20 次，`Frame.ts_sense` 单调递增，重复触发为 0；
- 拔掉相机/光电，`iter_frames()` 抛异常或返回空，`Inspector` 捕获后转 `RECHECK`，不能崩；
- 同一张图从文件源和相机源进入，结论一致（误差只来自压缩/曝光）。

## 2. 执行输出：`Dispatcher` / `MotorDriver`

### 2.1 契约

文件：`devices/base.py`

```python
class Dispatcher(abc.ABC):
    @abc.abstractmethod
    def dispatch(self, action: str, ctx: Dict) -> ActResult:
        """action: PASS / RECHECK / REJECT；ctx 含 frame_id、track_pos_mm 等。"""

@dataclass
class ActResult:
    ok: bool
    command: str
    ts_start: float
    ts_ack: float
    note: str = ""
```

`Inspector` 在决策后调用 `dispatcher.dispatch(res.action, ctx)`，把结果放进 `res.act`，并写 `act_ok/act_command/act_latency_ms/act_note`。

### 2.2 动作映射（可按机构改）

| action | 含义 | 建议动作 |
|---|---|---|
| `PASS` | 放行 | 不动作，传送带直通 |
| `RECHECK` | 复检 | PTK 挡板打到复检通道（35°），相机二次拍照/人工确认 |
| `REJECT` | 剔除 | 挡板 + 达妙推杆推到废品通道 |

### 2.3 三个电机驱动

文件：`devices/actuators.py`

| 类 | 真实设备 | 关键方法 | 现状 |
|---|---|---|---|
| `RoboMasterConveyor` | 大疆 M3508 + C620，CAN 1 Mbps | `connect()`、`set_speed_rpm()`、`stop()` | 桩，`NotImplementedError` |
| `PTKServoGate` | PTK 总线舵机，串口 | `connect()`、`set_angle(angle, move_ms)`、`move_for(action)` | 桩，角度 0/35/70° 占位 |
| `DamiaoPusher` | 达妙 DM4310/DM4340，CAN | `connect()`、`push()`、`retract()` | 桩，位置 `extend_pos=0.08` 占位 |
| `CompositeDispatcher` | 以上三者组合 | `connect()`、`dispatch()` | 骨架已写好，超时/未连接/异常路径已处理 |

加新执行机构：实现 `MotorDriver` 子类，然后在 `build_dispatcher()` 里替换/追加，`Inspector` 和界面不改。

### 2.4 执行确认与超时

`CompositeDispatcher.dispatch()` 当前行为：

- 未 `connect()` → `ActResult(False, "not_connected", ...)`；
- `NotImplementedError` → `ActResult(False, "...:not_implemented", ...)`；
- 其他异常 → `ActResult(False, "...:error", ...)`；
- PASS → 立即 `ok=True`；
- RECHECK/REJECT → 调舵机/推杆，当前立即返回 `ok=True`（**真机必须改成等编码器/限位**）。

真机建议：

```python
def dispatch(self, action, ctx):
    ts = time.time()
    if action == "PASS":
        return ActResult(True, "none", ts, time.time(), "放行")
    if action == "RECHECK":
        self.gate.set_angle(35, move_ms=120)
        ok = self.gate.wait_in_position(timeout_ms=300)   # 读总线回包
        return ActResult(ok, "gate@RECHECK", ts, time.time(),
                         "挡板到位" if ok else "挡板超时")
    if action == "REJECT":
        self.gate.set_angle(70, move_ms=120)
        self.pusher.push()
        ok = self.pusher.wait_in_position(timeout_ms=300)
        return ActResult(ok, "gate@REJECT+push", ts, time.time(),
                         "推杆到位" if ok else "推杆超时")
```

`ok=False` 时界面“执行失败”+1，记录 `act_ok=0`；连续失败应触发停线/报警（现在只记录，不自动停）。

### 2.5 时序补偿

`config.json` 的 `line` 段：

```json
"conveyor_speed_mm_s": 120,
"sensor_to_camera_mm": 40,
"camera_to_actuator_mm": 180,
"sim_cycle_ms": 900,
"sensor_debounce_ms": 150,
"actuator_timeout_ms": 300,
"queue_max": 20
```

`Inspector` 计算：

```text
delay_comp_ms = (sensor_to_camera_mm + camera_to_actuator_mm) / speed * 1000
track_pos_mm  = speed * (ts_decide - ts_trigger) / 1000
late          = (ts_decide - ts_trigger)*1000 > delay_comp_ms
```

当前 40+180 mm / 120 mm/s = 1833 ms，分析只要 20–100 ms，所以 `late=False`。真机把实测距离/速度填进去；如果 `late=True`，说明“决策还没做完瓶盖已经过了执行点”，需要提高节拍/换更快模型/把相机前移。

### 2.6 验收

- 模拟执行器 `fail_rate=0.1` 时，界面“执行失败”计数增加，记录 `act_ok=0`，程序不崩；
- 未 `connect()` 的 hardware 模式 → 明确 `not_connected`，不能假装成功；
- 三通道动作与 `PASS/RECHECK/REJECT` 一一对应，连续 20 只无错位。

## 3. 反馈记录：`Recorder` / `FeedbackSink`

### 3.1 契约

文件：`devices/base.py`

```python
class Recorder(abc.ABC):
    def record(self, row: Dict) -> None: ...
    def close(self) -> None: ...

class FeedbackSink(abc.ABC):
    def submit(self, row: Dict) -> None: ...
```

`Inspector._finish()` 每只调用一次 `recorder.record(res.to_record())`；界面“复检确认”调用 `feedback.submit(row)`。

### 3.2 已有实现

| 类 | 文件 | 输出 |
|---|---|---|
| `CsvRecorder` | `devices/base.py` | `运行结果/records.csv`，每行 flush |
| `MemoryRecorder` | `devices/base.py` | 内存 list，测试用 |
| `JsonlRecorder` | `devices/base.py` | 一行一个 JSON，便于后续接数据库 |
| `CsvFeedbackSink` | `devices/base.py` | `运行结果/recheck_feedback.csv` |

### 3.3 52 列 schema（`h1.2`）

完整字段在 `devices/base.py: RECORD_FIELDS`，分组：

| 组 | 字段 |
|---|---|
| 版本/身份 | `schema_version`、`ts`、`frame_id`、`image_path`、`label` |
| 质量 | `quality_ok`、`quality_reason`、`mean_lum`、`sharpness`、`center_offset` |
| 特征 | `notch`、`dark`、`purity`、`peak`、`anomaly_score`、`worst_feature` |
| 特征模型 | `feat_class`、`feat_conf`、`feat_proba` |
| 深度模型 | `deep_class`、`deep_conf`、`deep_defect`、`deep_proba`、`deep_available`、`deep_latency_ms` |
| 融合/决策 | `fusion_mode`、`risk`、`pred_class`、`pred_conf`、`class_proba`、`action`、`reason`、`is_unknown`、`rule` |
| 执行 | `act_ok`、`act_command`、`act_latency_ms`、`act_note` |
| 产线/时序 | `track_pos_mm`、`delay_comp_ms`、`queue_depth`、`late`、`ts_trigger`、`ts_capture`、`ts_analyze`、`ts_decide`、`ts_act`、`ts_ack`、`ts_feedback`、`analysis_ms`、`elapsed_ms` |
| 后端 | `backend`（`feature` / `feature+deep`） |

### 3.4 加字段

1. 在 `devices/base.py` 的 `RECORD_FIELDS` 末尾加字段（不要插入中间，CSV 顺序会变）；
2. 在 `core/pipeline.py: InspectionResult.to_record()` 里填值；
3. 升 `SCHEMA_VERSION`（例如 `h1.3`）；
4. 旧文件不用手改：`CsvRecorder` 检测表头不一致会自动改名为 `records.csv.old_YYYYmmdd_HHMMSS`。

### 3.5 换成 SQLite（示例）

```python
class SqliteRecorder(Recorder):
    def __init__(self, path):
        self.conn = sqlite3.connect(path)
        cols = ", ".join(RECORD_FIELDS)
        qs = ", ".join("?" for _ in RECORD_FIELDS)
        self.conn.execute(f"CREATE TABLE IF NOT EXISTS records ({cols})")
        self._sql = f"INSERT INTO records ({cols}) VALUES ({qs})"

    def record(self, row):
        self.conn.execute(self._sql, [row.get(k) for k in RECORD_FIELDS])
        self.conn.commit()

    def close(self):
        self.conn.close()
```

然后在 `Inspector.from_config()` 里把 `CsvRecorder` 换成 `SqliteRecorder` 即可；界面和判断逻辑不动。

### 3.6 反馈闭环

- 界面选中记录 → “复检确认” → 选最终处置/备注 → `CsvFeedbackSink.submit()`；
- 后续可加：复检结果回写训练集（主动学习）、按 `frame_id` 关联 MES 工单、统计“复检后改判率”。

### 3.7 验收

- 连续 20 只后 `records.csv` 行数 = 20，表头与 `RECORD_FIELDS` 一致；
- 中途强退，已写入行不丢（每行 flush）；
- 复检确认后 `recheck_feedback.csv` 有对应 `frame_id`；
- 表头升级后旧文件自动改名，不混行。

## 4. 可视化：替换/扩展界面

### 4.1 原则

- `core/` 不 import tkinter；`ui/app.py` 只做“调用 Inspector + 展示 InspectionResult + 收集参数”。
- 换 Web/大屏：新界面同样构造 `Inspector`，订阅结果即可；判断逻辑零改动。
- 界面线程模型：Tk 主线程只碰控件；检测在**单线程推理池**里跑，通过 `queue.Queue` 回主线程，`after(80)` 轮询。

> 为什么是单线程池：实测 CUDA 首次推理在“新线程”里会重新初始化（1.6–16 s）。把预热和所有推理放在同一个常驻线程，首张才能稳定 80–100 ms。

### 4.2 最小代码

```python
from core.pipeline import Inspector

ins = Inspector.from_config("config.json", dispatcher_mode="sim",
                            record=True, keep_debug=False)
res = ins.inspect("数据/dataset/images/val/notch/img_1_046.png", dispatch=True)
print(res.action, res.pred, res.risk, res.fusion.reason, res.elapsed_ms)
```

批量：

```python
for res in ins.inspect_many(paths, dispatch=False):
    ...
```

### 4.3 界面要展示的最小字段

| 字段 | 用途 |
|---|---|
| `res.action` | 大结论 PASS/RECHECK/REJECT |
| `res.pred` / `res.conf` | 类别 + 置信度 |
| `res.risk` | 融合风险条 |
| `res.anomaly_score` / `res.deep.defect_score` | 两个模型各自的证据 |
| `res.fusion.reason` / `detail` | 给操作员/评委的解释 |
| `res.features` + `res.zs` | 诊断页四特征/阈值/倍数 |
| `res.act` | 执行命令、成功/失败、耗时 |
| `res.elapsed_ms` | 节拍 |

### 4.4 参数写回

```python
ins.update_decision(low=0.5, high=0.9, conf_min=0.97)  # 立即生效
ins.save_config()                                      # 写回 config.json
```

### 4.5 换界面时不要做的事

- 不要在界面线程里直接 `torch` 推理（会卡 UI，且 CUDA 线程问题）；
- 不要把阈值硬编码在界面里（从 `config.json`/`Inspector` 读）；
- 不要把 `CLASSES` 顺序改掉（必须与 `model.pth` 的 `class_names` 一致）。

## 5. 其它扩展点

### 5.1 新增缺陷类别

1. `config.json` 的 `classes` / `class_cn` / `defect_classes` 加新类；
2. `core/types.py: CLASSES` 同步（**顺序必须与模型输出一致**）；
3. 重新训练/替换 `model.pth` 和 `classifier.json`；
4. 若是新特征，改 `core/features.py` + `baseline.json`；
5. 界面会自动读 `class_cn` 显示中文，不用改 UI 代码。

### 5.2 换/加分类模型

`core/deep_model.py: DeepModel.predict()` 返回 `ModelOutput`。换模型只改 `load()/predict_batch()`，保持：

```python
ModelOutput(name="deep", available=True, probs={...四类...},
            pred=..., conf=..., defect_score=..., latency_ms=...)
```

`core/fusion.py` 只认 `ModelOutput`，不认具体网络。

### 5.3 新增融合方式

在 `core/fusion.py: fuse()` 里加 `mode == "M4"` 分支，返回 `FusionResult`；`config.json` 的 `fusion.modes` 加 `"M4"`，界面下拉自动出现（界面读 modes/标签表）。

### 5.4 新增输入/输出协议

- 输入：实现 `FrameSource.iter_frames()`；
- 输出：实现 `Dispatcher.dispatch()`；
- 记录：实现 `Recorder.record()`；
- 反馈：实现 `FeedbackSink.submit()`。

四个都是 `abc.ABC`，接口稳定；新增实现不需要动 `core/`。

## 6. 异常契约

| 场景 | 行为 | 记录 |
|---|---|---|
| 读图失败/无图像 | `RECHECK`，`act=stop_line` | `error=感知失败...`，`quality_ok=0` |
| 质量门不过（暗/糊/偏/尺寸） | `RECHECK` | `quality_reason` 写具体原因 |
| 特征测量异常 | `RECHECK`，`act=stop_line` | `error=特征测量失败...` |
| 深度模型不可用 | 自动回退 M0，继续判 | `deep_available=0`，`backend=feature` |
| 模型置信不足 | 仍按 risk 决策；`REJECT` 时标 `is_unknown=1` | `reason` 写“类别置信不足” |
| 执行未连接/超时 | `ActResult(ok=False)` | `act_ok=0`，界面“执行失败”+1 |
| 记录写失败 | 不影响检测，`record_error` 存错误 | 界面 footer 提示 |

原则：**任何不确定都往 RECHECK 靠，绝不静默 PASS。**
