# 模型方案总结：单一模型 vs M3 双模型融合

> 版本：2026-11-08  
> 数据：课程教学合成图 240 张（train 160 / val 40 / test_unlabeled 40），四类 normal / notch / scratch / stain。  
> 结论只代表这套 40 张验证集和这套合成数据，**不代表真实工业现场性能**。

---

## 0. 结论摘要

- 单一特征模型：val **39/40 = 97.5%**，错例 `img_2_042`（划痕→污渍，仍 REJECT）。
- 单一基础版深度模型：val **39/40 = 97.5%**，错例 `img_2_045`（划痕→正常，缺陷分 0.217，靠阈值进 RECHECK）。
- **M3 双模型融合：val 40/40 = 100%，漏检 0，正常误剔 0，复检 1 只（2.5%）**，平均 22.7 ms/张。

一句话：**两个单模型的错例正好互补；M3 不是“堆模型”，而是用两路独立证据换零漏检和可解释性。**

## 1. 手里有哪几个模型

### 1.1 三条证据链

| 链路 | 具体模型 | 输入 | 输出 | 训练方式 | 依赖 |
|---|---|---|---|---|---|
| A. 特征异常分 | 正常品 median/MAD 基线 + 稳健 z | 四维手工特征 | 异常分 0–1 | 无监督，只用正常品拟合 | numpy |
| B. 特征分类器 | 手写 softmax 回归（logreg） | 四维手工特征 | 四类概率 | train 160 张，5 折 CV 选型 | numpy |
| C. 深度分类器 | MobileNetV3-Small（基础版 `model.pth`） | 512×512 RGB | 四类概率 + 缺陷分 | 迁移学习，只训练最后输出层 | torch + torchvision |

特征链路的具体做法：

```text
色度掩膜找圆心/半径
→ 极坐标摊平 720×160
→ 每行减中位数得到残差
→ 量四个特征：
   notch   缺口率
   dark    暗斑面积（污渍）
   purity  直线纯度（划痕）
   peak    直线带点数
→ 正常品 median/MAD 算稳健 z
→ 异常分 = 1 - exp(-max_z / 2)
```

深度链路的预处理与基础版一致：

```text
RGB
→ ToTensor
→ Normalize(checkpoint["mean"], checkpoint["std"])
→ MobileNetV3-Small
→ softmax 四类
→ 缺陷分 = P(缺口) + P(划痕) + P(污渍)
```

### 1.2 它不是“大模型”

- MobileNetV3-Small 是**轻量 CNN**，约 2.5M 参数，`model.pth` 只有 6 MB。
- 基础版只训练了最后的四分类输出层，不是从零训练，也不是大语言模型。
- 特征分类器更小：四个特征 + 一个 softmax 回归。
- 两套模型都跑在本地，不联网。

## 2. 单一方案实测

### 2.1 只用特征（M0）

| 指标 | 结果 |
|---|---|
| 准确率 | 39/40 = 97.5% |
| 漏检（缺陷→PASS） | 0 |
| 正常误剔（正常→REJECT） | 0 |
| 复检 | 0 |
| 动作 | PASS 10 / RECHECK 0 / REJECT 30 |
| 纯特征耗时 | 约 14 ms/张 |
| 错例 | `img_2_042`：真值 scratch，判 stain，risk 0.987 → REJECT |

特点：

- 优点：不需要缺陷样本；可解释；能抓“训练集没见过的异常”；CPU 也能跑。
- 缺点：四个手工特征对划痕/污渍的区分有上限；类别语义弱；基线对光照/工装敏感。

> 统一流水线里的 M0 显示 22.2 ms，是因为 `Inspector` 仍会前向一次深度模型但不用它的结果；纯特征单独跑约 14 ms。

### 2.2 只用基础版深度模型

按基础版原生阈值：缺陷分 `<0.20` 放行，`0.20–0.80` 复检，`≥0.80` 剔除。

| 指标 | 结果 |
|---|---|
| 准确率 | 39/40 = 97.5% |
| 漏检 | 0 |
| 正常误剔 | 0 |
| 复检 | 3/40 = 7.5% |
| 动作 | PASS 9 / RECHECK 3 / REJECT 28 |
| 耗时 | 约 10 ms/张（GPU warm） |
| 错例 | `img_2_045`：真值 scratch，判 normal，缺陷分 0.217 → RECHECK |

注意：`img_2_045` **不是漏检**，因为缺陷分 0.217 超过 0.20，动作是 RECHECK；但它说明基础版分类头确实会把划痕看成正常，只是靠阈值兜底。

另一只正常品 `img_0_050` 被深度模型给了 0.369 的缺陷分，单深度方案会把它送复检——这是深度模型的过度报警。

### 2.3 总对比

| 方案 | 准确率 | 漏检 | 正常误剔 | 复检 | 平均耗时 | 动作 P/R/J |
|---|---|---|---|---|---|---|
| 纯特征（M0） | 39/40 = 97.5% | 0 | 0 | 0 | 约 14 ms | 10/0/30 |
| 纯基础版深度 | 39/40 = 97.5% | 0 | 0 | 3（7.5%） | 10 ms | 9/3/28 |
| **M3 融合** | **40/40 = 100%** | **0** | **0** | **1（2.5%）** | **22.7 ms** | **9/1/30** |

四条融合模式的完整结果（同一套 val、同一套阈值）：

| 模式 | 逻辑 | 准确率 | 漏检 | 正常误剔 | 复检率 | 平均耗时 | 动作 P/R/J | unknown |
|---|---|---|---|---|---|---|---|---|
| M0 | 纯特征 | 97.50% | 0 | 0 | 0% | 22.2 ms | 10/0/30 | 2 |
| M1 | 特征异常分门卫 + 深度分诊 | 97.50% | 0 | 0 | 12.5% | 22.6 ms | 5/5/30 | 8 |
| M2 | 深度缺陷分门卫 + 特征分诊 | 97.50% | 0 | 0 | 2.5% | 22.7 ms | 9/1/30 | 0 |
| **M3** | **双模型证据融合** | **100.00%** | **0** | **0** | **2.5%** | **22.7 ms** | **9/1/30** | **6** |

选择规则按小组优先级：**零漏检 > 准确率 > 少误剔 > 低延迟 > 低复检**。M3 在 val 上 40/40，漏检/误剔都是 0，因此设为默认。

## 3. M3 融合的具体算法

设：

- `a` = 特征异常分（0–1，越大越异常）
- `d` = 深度缺陷分 = `P(notch)+P(scratch)+P(stain)`
- `p_feat`、`p_deep` = 两个模型对四类的概率
- `w = 0.5` = 深度模型权重

```text
risk = max(a, d)                    # 任一模型认为异常，都不能轻易放行
p     = (1-w) * p_feat + w * p_deep # 加权四类概率
pred  = argmax(p)
```

决策：

```text
if 质量门不过:
    RECHECK（感知异常，停线/人工接管）
elif risk >= high:
    REJECT
elif risk >= low:
    RECHECK
elif pred == normal and p_normal >= 0.9:
    PASS
else:
    RECHECK
```

当前阈值：

```text
low      = 0.3607
high     = 0.8371
conf_min = 0.97
pass_normal_prob = 0.9
```

- `low/high` 来自训练集正常品与缺陷品的异常分空档：正常最高 0.3342，缺陷最低 0.8636。
- **没有在 val 上调阈值**，避免“用验证集调参”。
- `demo_recheck` 是另一个演示预设：low=0.8214、high=0.9868、conf=0.95，专门为了让复检分支出现。

### 3.1 为什么是 `max` + 加权，而不是简单投票

- **`max` 是“安全或门”**：只要任一模型报警，就不能 PASS。投票/平均会让一个模型的低分压过另一个模型的高分，容易出现“两票通过”。
- **概率加权是“软证据”**：类别判断上不搞“谁嗓门大听谁”，而是 0.5/0.5 融合；M3 的类别准确率因此到 40/40。
- **两者分工**：`max` 管“要不要放行”，加权概率管“像哪一类”。

### 3.2 unknown 是什么

`is_unknown=True` 表示“动作是 REJECT，但类别置信不足”：

- `pred == normal` 或 `max(p) < conf_min`，同时 `risk >= high`；
- 动作仍然 REJECT，不会放行；
- val 上 M3 有 6 个 unknown，**全部是缺陷**，不是漏检；
- 它的作用是提示“建议人工确认类别”，不是“模型不确定所以放过”。

## 4. 两个样本说明互补

### 4.1 `img_2_045`：特征补深度的“漏看”

| 项 | 值 |
|---|---|
| 真值 | scratch |
| 特征异常分 | **0.9939** |
| 深度缺陷分 | **0.2168** |
| 深度单独预测 | normal（靠 0.217 进 RECHECK） |
| M3 risk | **0.9939** → REJECT |
| M3 预测 | scratch |

深度模型只给了 0.217 的缺陷分，单靠它会进复检；特征异常分 0.994，因为划痕的直线纯度和带点数明显偏离正常品。M3 取 max 后直接 REJECT，并判 scratch。

### 4.2 `img_2_042`：深度补特征的“看错”

| 项 | 值 |
|---|---|
| 真值 | scratch |
| 特征模型预测 | stain（错） |
| 深度模型预测 | scratch（对） |
| 特征异常分 | 0.9868 |
| M3 预测 | scratch（对） |
| M3 risk | 1.000 → REJECT |

特征模型把划痕判成污渍，深度模型判对；M3 加权后纠正类别，同时 risk=1.0 仍然 REJECT。

### 4.3 M3 的代价样本 `img_0_050`

| 项 | 值 |
|---|---|
| 真值 | normal |
| 特征异常分 | 0.0964 |
| 深度缺陷分 | 0.3693 |
| M3 risk | 0.3693 → RECHECK |
| 结果 | 正常品进复检（不是误剔） |

这是 `max` 保守策略的代价：深度模型过度报警，特征模型认为正常，但 max 让 risk 略高于 low=0.3607。M3 的 1 只复检就是它。

## 5. 新方案相较于单一方案的优势

1. **零漏检更稳**
   `risk=max(a,d)` 让任一模型报警都不能 PASS。单一深度模型错判 `img_2_045` 时只进复检；单一特征模型错判 `img_2_042` 时类别错但仍是 REJECT。M3 用两路独立证据把“静默放行”的概率压到最低。

2. **能处理训练集没见过的异常**
   特征异常分只用正常品拟合 median/MAD，不依赖缺陷类别；深度模型只认识四类。真实产线出现新缺陷时，深度模型可能给低缺陷分，异常分会把它拉进复检/剔除。这是单一四分类模型做不到的。

3. **类别判断更准**
   深度模型补上特征模型的 `img_2_042` 错例；M3 从 39/40 到 40/40。概率加权比“单一模型硬判”更稳。

4. **可解释、可审计**
   界面/记录同时保留：
   - 特征侧：缺口率、暗斑面积、直线纯度、带点数、z 值；
   - 深度侧：四类概率、缺陷分；
   - 融合侧：risk、规则、是否 unknown。
   单一深度是黑盒；单一特征缺少语义置信。M3 两边都能给依据，答辩和产线追责都方便。

5. **工程上可降级、可替换**
   深度不可用时自动回退 M0，界面/三态/记录/仿真都能跑；特征基线漂移时也能单独重标。单一深度方案没 torch/GPU 直接不可用；单一特征方案又难提准确率。M3 是“可降级的冗余”。

6. **成本可接受**
   M3 22.7 ms/张，只比纯深度多约 12 ms；相对传送带 1833 ms 的延时预算可以忽略，不影响节拍。

## 6. 代价与边界

- **数据边界**：40/40 是 40 张教学合成图的结果，不能证明真实产线 100%；换真实数据必须重新标定基线、阈值和模型。
- **深度模型容量有限**：只训练最后一层，价值是“补特征模型的错例”，不是替代特征模型。
- **M3 会多一次复检**：val 上 1 只正常品 `img_0_050` 因深度过度报警进复检；这是保守策略的代价，不是漏检/误剔。
- **依赖 torch**：没 GPU 可回退 M0 或 CPU；CPU 上深度分支会慢一些。
- **复杂度更高**：多一套正常品基线、多一组融合参数，标定和解释成本比单模型高。
- **不是所有场景都该用 M3**：如果现场只有四类、深度模型很稳、算力又紧，M0 或纯深度更简单；M3 的价值在“零漏检优先 + 有未知缺陷风险”的场景。

---

## 7. 选型建议

| 场景 | 建议 |
|---|---|
| 没有 GPU / 没有 torch / 只做快速演示 | M0（纯特征） |
| 只有四类、深度模型稳定、追求最低延迟 | 纯深度或 M2 |
| 零漏检优先、可能有未知缺陷、需要可解释 | **M3（默认）** |
| 答辩/视频要展示 RECHECK 分支 | `demo_recheck` 预设 + M3 |
| 深度模型不可用/加载失败 | 自动回退 M0，记录 `mode_fallback=M0` |

## 10. 一句话给评委

> 单特征模型“看得懂但认不全”，单深度模型“认得准但说不清、还可能漏看新缺陷”；M3 让两者互相当“第二双眼睛”，再用 `max` 把安全阈值收紧——**准确率从 39/40 到 40/40，漏检和误剔都是 0，代价只是多 12 ms 和 1 只正常品复检。**
